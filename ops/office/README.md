# PZ-Med Office

Закрытый внутренний реестр поставок PZ-Med на `https://pz-med.ru/office/`.

Хранит:
- заказчиков (государственные/частные);
- ИНН, договор и срок поддержки;
- первую установленную версию и дату;
- текущую версию и историю обновлений;
- Installation ID, License ID, build commit и SHA-256;
- персональные архивы поставок/обновлений;
- готовый текст, который отправляется заказчику вместе с архивом;
- необязательные служебные примечания и контакт ИТ.

## Автоматические поставки

После создания карточки заказчика Office предлагает `Сформировать поставку`.
Веб-приложение не запускает shell-команды и не имеет доступа к приватному signing key: оно только помещает строго типизированное задание в SQLite. Отдельный root-only systemd worker берёт задание, проверяет release-репозиторий PZ-Med, создаёт/переиспользует постоянные Installation ID и License ID, собирает подписанный offline-архив и автоматически записывает в карточку версию, commit, SHA-256, дату и путь к архиву.

Для установленного заказчика доступно `Сформировать обновление`. Update-архив персонализирован под Installation ID и исходную версию. На стороне клиники установщик сохраняет рабочие данные, создаёт резервную копию SQLite-БД, заменяет vendor-код, обновляет зависимости из offline wheelhouse, запускает production preflight и миграции от непривилегированного пользователя приложения.

Если код изменился после последнего официального релиза, Office просит выбрать только значимость изменения: `patch`, `minor` или `major`. Номер следующей версии рассчитывается автоматически. Если код не менялся, другой заказчик получает ту же официальную версию.

## Встроенная почта

Office может работать как защищённый почтовый клиент для рабочего ящика `@pz-med.ru`:

- чтение входящих через IMAP;
- просмотр отправленных и других стандартных папок, если сервер их публикует;
- просмотр писем только как безопасного текста: HTML из внешних писем не исполняется;
- отправка через SMTP;
- ответы с `In-Reply-To` и `References`;
- входящие и исходящие вложения до 10 МБ суммарно;
- скачивание вложений из входящих писем;
- поиск по отправителю, получателю и теме среди последних писем.

Почта не копируется в SQLite Office: источником истины остаётся сам IMAP-ящик. Пароль почты хранится только в `/etc/pz-med-office.env`.

Минимальная конфигурация для Джино:

```text
OFFICE_MAIL_ADDRESS=ivan@pz-med.ru
OFFICE_MAIL_PASSWORD=<пароль почтового ящика>
```

Необязательные параметры уже имеют безопасные значения по умолчанию:

```text
OFFICE_MAIL_DISPLAY_NAME=PZ-Med
OFFICE_MAIL_IMAP_HOST=mail.jino.ru
OFFICE_MAIL_IMAP_PORT=993
OFFICE_MAIL_SMTP_HOST=smtp.jino.ru
OFFICE_MAIL_SMTP_PORT=465
OFFICE_MAIL_MAX_ATTACHMENT_MB=10
```

После изменения `/etc/pz-med-office.env` нужно выполнить:

```bash
sudo systemctl restart pz-med-office
```

## Безопасность

- серверная авторизация, пароль хранится только в виде хэша;
- CSRF-защита всех изменяющих запросов;
- ограничение неудачных попыток входа;
- Secure/HttpOnly/SameSite cookie;
- `noindex`, `no-store` и защитные HTTP-заголовки;
- база данных находится вне web-root: `/var/lib/pz-med-office/office.sqlite3`;
- скачиваемые архивы находятся вне web-root: `/var/lib/pz-med-office/releases/`;
- секреты Office и пароль почты находятся вне Git: `/etc/pz-med-office.env`;
- HTML из входящих писем преобразуется в обычный текст перед отображением;
- внешние изображения и скрипты из писем не загружаются;
- приватный release signing key никогда не передаётся веб-процессу;
- `pz-med-office.service` работает от непривилегированного `pz-med-office`;
- `pz-med-office-release-worker.service` — отдельный root-only worker с фиксированным набором release-действий.

## Развёртывание

Сначала рабочая release-копия PZ-Med должна содержать актуальные release-скрипты и существующий vendor signing key. Затем:

```bash
clinic-test-update
pz-site-update
sudo bash /var/www/pz-med.ru/ops/office/deploy_office.sh
```

Повторный запуск `deploy_office.sh` обновляет код, но сохраняет базу, пароль, историю и созданные архивы. Почтовые переменные в `/etc/pz-med-office.env` также сохраняются.

## Данные

Основная база Office:

```text
/var/lib/pz-med-office/office.sqlite3
```

Архивы, доступные для скачивания из Office:

```text
/var/lib/pz-med-office/releases/
```

Закрытый release-state официальной версии:

```text
/var/lib/pz-med-release/state.json
```

Закрытый реестр постоянных customer Installation ID / License ID остаётся в release-инфраструктуре PZ-Med и не публикуется через сайт.
